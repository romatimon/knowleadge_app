# Knowledge App

**Внутренняя база знаний для сотрудников.**

Knowledge App объединяет рабочие инструкции, типовые ситуации, нормативные сведения, сроки испытаний и нормы отбора образцов в одном веб-интерфейсе. Приложение помогает сотрудникам быстрее находить ответы на повседневные вопросы и работать с единым актуальным источником информации.

Проект построен на Streamlit, хранит данные в SQLite и поддерживает контейнеризованное развёртывание через Docker.

## Возможности

### Для сотрудников

- навигация по рабочим разделам и веткам;
- закреплённые и недавно обновлённые материалы на главной странице;
- поиск по материалам базы знаний;
- глобальный поиск по всей базе и отдельный поиск внутри раздела;
- просмотр типовых рабочих ситуаций, справок и правил;
- доступ к инструкциям и пошаговым алгоритмам;
- просмотр сроков проведения испытаний;
- просмотр сроков действия сертификатов и деклараций;
- информация по испытаниям аккумуляторов и батарей;
- нормы отбора образцов по группам продукции;
- поиск по содержимому таблиц;
- подсветка найденного текста.

### Для администратора

- отдельный вход по паролю;
- создание, переименование и выбор назначения разделов;
- настройка порядка и видимости разделов;
- безопасное удаление разделов в архив и восстановление;
- создание, редактирование, упорядочивание и архивирование веток;
- перенос материалов между совместимыми ветками;
- добавление материалов подходящего типа в каждый раздел;
- фильтрация административного списка по разделу и типу материала;
- настройка публикации и порядка материалов внутри раздела;
- отдельные экраны настройки структуры и редактирования данных таблицы;
- необязательная редактируемая памятка над каждой таблицей;
- переименование колонок без потери связанных значений;
- добавление, удаление и вставка строк непосредственно в табличном редакторе;
- импорт CSV и Excel с предпросмотром и сопоставлением колонок;
- добавление импортированных строк или полная замена данных с подтверждением;
- выгрузка любой таблицы в CSV и Excel;
- архивирование и восстановление материалов;
- добавление, редактирование и удаление материалов FAQ;
- управление инструкциями и алгоритмами;
- редактирование нормативных таблиц;
- указание краткого описания, ключевых слов, даты обновления и источника;
- статусы «Актуально», «Требует проверки» и «Черновик»;
- дата следующей проверки и предупреждение о просроченной актуальности;
- автоматическое скрытие черновиков от сотрудников;
- закрепление ключевых материалов на главной странице;
- предварительный просмотр Markdown перед сохранением;
- импорт и экспорт текстовых материалов в `.md`;
- создание черновой копии любого материала;
- отдельная страница контроля актуальности и структуры;
- упрощённый редактор по схеме «раздел → ветка → материал → форма»;
- автоматическое сохранение изменений в SQLite;
- создание резервной копии базы перед изменением данных.

## Структура базы знаний

При первом запуске приложение создаёт пять рабочих разделов. Администратор может
переименовывать, скрывать, архивировать и создавать новые разделы и ветки без
изменения исходного кода:

| Раздел | Содержание |
|---|---|
| Работа с клиентом | квалификация запроса, красные флаги, проверка благонадёжности и FAQ |
| Оформление документов | заявка, макет, ФГИС и особые процедуры оформления |
| Испытания и образцы | ввоз, отбор, лаборатории, АСП, протоколы испытаний, матрицы и нормы |
| Сопровождение | инспекционный контроль, переоформление, дореализация, нормы и сроки |
| Справочник и внутренние процессы | термины, регламенты, схемы и передача дел |

В каждом разделе создаются ветки «Инструкции», «Шаблоны», «FAQ», «Чек-листы»
и «Матрицы и нормы». Ветка определяет тип своего содержимого. Дополнительные
ветки можно создавать через режим администратора. Глубже уровня
«раздел → ветка → материал» структура не вкладывается.

Клиентские проекты, договоры, ЭЦП и другие конфиденциальные файлы в приложении
не хранятся. Для них следует использовать отдельное защищённое файловое хранилище.

## Как работает приложение

```text
Пользователь
    │
    ▼
Streamlit-интерфейс
    │
    ├── глобальный поиск и поиск внутри раздела
    ├── боковая навигация по рабочим направлениям
    ├── фильтр по веткам внутри раздела
    └── просмотр материалов
            │
            ▼
        SQLite

Администратор
    │
    ├── вход по паролю
    ├── добавление и редактирование
    └── удаление материалов
            │
            ▼
    резервная копия текущей базы
            │
            ▼
        обновление SQLite
```

Единственное рабочее хранилище приложения — `knowledge.db`.

## Хранение данных

Приложение использует каталог, заданный переменной `DATA_DIR`.

- при локальном запуске данные по умолчанию находятся в корне проекта;
- в Docker используется каталог `/data`;
- `knowledge.db` и каталог `backups/` сохраняются на сервере независимо от пересборки контейнера.
- перед каждым изменением создаётся проверенная резервная копия SQLite;
- приложение хранит не более десяти автоматических копий вида `knowledge_20*.db`; ручные и именованные копии не удаляются.
- настройки боковой навигации хранятся в таблице `content_sections`;
- ветки и их типы хранятся в таблице `content_branches`;
- универсальные материалы разделов хранятся в таблице `content_items`;
- статус и даты проверки хранятся вместе с материалом в `content_items`;
- при обновлении старой базы новый рабочий каркас и необходимые поля добавляются
  автоматически после создания резервной копии;
- удалённый раздел сначала перемещается в архив, поэтому его можно восстановить.

Файлы с корпоративными материалами исключены из Git и Docker-образа.

## Безопасность

- пароль администратора передаётся через переменную окружения;
- стандартного резервного пароля в исходном коде нет;
- если `ADMIN_PASSWORD` не настроен, административный режим отключается;
- `.env` и базы SQLite не включаются в Docker-образ;
- пользовательский текст экранируется перед отображением через HTML;
- данные администратора сравниваются безопасным методом без обычного строкового сравнения.

Приложение предназначено для внутреннего использования. Доступ к порту `8501` следует ограничивать корпоративной сетью, VPN, firewall или обратным прокси-сервером с авторизацией.

## Конфигурация

Скопируйте `.env.example` в `.env` и задайте пароль администратора:

```env
ADMIN_PASSWORD=your-strong-admin-password
IMAGE_TAG=2026.09.02-1
HOST_DATA_DIR=/home/roman/knowledge_app
```

Для локального запуска используется только `ADMIN_PASSWORD`. Переменные `IMAGE_TAG`
и `HOST_DATA_DIR` нужны при развёртывании на сервере. Файл `.env` не должен
добавляться в Git.

## Локальный запуск через Docker Compose

Клонируйте репозиторий:

```bash
git clone https://github.com/romatimon/knowleadge_app.git
cd knowleadge_app
```

Убедитесь, что в корне проекта есть `knowledge.db` и каталог `backups/`, затем
запустите проект из Git Bash:

```bash
docker compose -f compose.local.yml up -d --build
```

Приложение будет доступно по адресу:

```text
http://localhost:8502
```

Посмотреть состояние и журналы:

```bash
docker compose -f compose.local.yml ps
docker compose -f compose.local.yml logs -f knowledge-app
```

Остановить приложение:

```bash
docker compose -f compose.local.yml down
```

После изменения кода снова выполните
`docker compose -f compose.local.yml up -d --build`. Локальный Compose собирает
образ `knowledge-app:local` из текущих файлов и не загружает рабочий образ с
сервера.

## Локальный запуск без Docker

При необходимости приложение можно запустить непосредственно в Python:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
$env:ADMIN_PASSWORD = "ваш-пароль"
streamlit run app.py
```

В Git Bash команда установки пароля выглядит так:

```bash
export ADMIN_PASSWORD="ваш-пароль"
streamlit run app.py
```

## Публикация проверенной версии

После локальной проверки назначьте образу отдельную версию и отправьте её в
Docker Hub. Пример для Git Bash:

```bash
VERSION=2026.09.02-1
docker tag knowledge-app:local rtimonin569/knowledge_app:$VERSION
docker login
docker push rtimonin569/knowledge_app:$VERSION
```

Для каждого выпуска задавайте новую версию. Файлы `.env`, `knowledge.db` и каталог
`backups/` исключены из контекста сборки и не попадают в образ.

## Развёртывание через Portainer

Перед первым запуском на сервере должны находиться:

```text
/home/roman/knowledge_app/knowledge.db
/home/roman/knowledge_app/backups/
```

Создайте Stack из `docker-compose.yml` и добавьте переменные окружения:

```text
ADMIN_PASSWORD=<надежный пароль администратора>
IMAGE_TAG=2026.09.02-1
HOST_DATA_DIR=/home/roman/knowledge_app
```

`ADMIN_PASSWORD` хранится только в настройках Stack. Не добавляйте реальный пароль в Compose-файл, GitHub или Docker-образ.

При обновлении опубликуйте образ с новым тегом, измените `IMAGE_TAG`, затем
выполните **Pull and redeploy** в Portainer. Рабочая база и резервные копии
останутся на сервере благодаря bind mounts.

## Запуск Compose на сервере

При необходимости production-конфигурацию можно запустить без Portainer. Создайте
на сервере `.env` на основе `.env.example`, затем выполните:

```bash
docker compose pull
docker compose up -d
```

Посмотреть журналы:

```bash
docker compose logs -f knowledge-app
```

Остановить приложение:

```bash
docker compose down
```

Корпоративные данные подключаются к контейнеру отдельно. Не добавляйте базу знаний в GitHub или публичный Docker registry.

## Правила добавления материалов

Используйте FAQ для одного конкретного вопроса сотрудника, инструкцию — для
повторяющегося процесса, шаблон — для готового текста, чек-лист — для контроля,
а справочную таблицу — для сроков, количеств и других точных значений. Текстовые
материалы хранятся как Markdown и могут импортироваться или выгружаться в `.md`.

Для каждого материала укажите название, краткое описание, текст, ключевые слова,
раздел и ветку, источник при его наличии и дату обновления. Для новых текстовых
материалов редактор предлагает единый Markdown-каркас:

1. 🎯 Назначение.
2. 📌 Основные блоки.
3. ⚙️ Алгоритмы.
4. ⚠️ Важно.
5. 📚 Справочная информация.

Один шаг должен описывать одно действие и начинаться с глагола: «Проверить»,
«Запросить», «Создать», «Передать». Если шаг зависит от условия, используйте
формулировку «Если …, то …». Не создавайте FAQ и инструкцию с одинаковым
содержанием: краткий FAQ должен направлять сотрудника к одной основной инструкции.

Проект развивается как единый внутренний рабочий инструмент для сотрудников.
